# 设计师 / Bug 修复指南（2026-11-23 Cycle 7）

## 三个 bug 的共性

都是“先破坏、后失败”：

1. 配置重载先让 CSS 改内存，类型错误可能留下半套配置。
2. 命令声明 `MinArgs=1`，但方法内部有 0 参数列表分支，分支永远走不到。
3. 自动抽骰先移除旧 Dice，再抽；抽不到时玩家空手。

修复原则：**先验证/预检，再执行破坏性操作**。

## 设计决策

- 配置：新增只读 `ConfigFileValidator`，用宽松 JSON 选项（注释、尾逗号、大小写不敏感、忽略未知字段）反序列化一份临时 `PluginConfig`；失败则抛错，不调用 CSS Reload。
- 命令：`CommandGiveDice` 的 `MinArgs` 改为 0，让已有的列表分支可达；用法字符串仍写 `<player> [dice]`。
- 自动抽骰：在遍历玩家前检查 `GetDrawablePool().Count == 0`，空池直接返回，不执行 `RemoveDiceForPlayer`。

## 边界

- 不做 CSS Reload 的替代实现；只做前置类型校验。
- 不改变 `!givedice` 的权限、匹配规则、随机逻辑。
- 不在空池时尝试“恢复旧 Dice”；只是不先删除。
- 不顺手改 AutoRoll 的替换策略、间隔、计数。

## 验收

- 类型错误被拦截，旧配置不变。
- 0 参数列表可达，正常给 Dice 不受影响。
- 空池不产生破坏性副作用。
- 新增断言覆盖配置校验与命令 arity。
