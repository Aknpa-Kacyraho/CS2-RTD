# 设计师 / UI 指南（2026-11-23 Cycle 4）

## 设计原则

- 信息优先：先给结论（有几个、什么稀有度），再给细节（效果、冷却）。
- 一套视觉语言：稀有度颜色、圆点、缩进、分隔符只在一个 helper 里定义。
- 克制：不新增命令、不改文案语义、不做花哨动画；聊天框是低带宽界面。
- 可回退：任何一行都能退回旧文案，不把 UI 状态写进配置或存档。

## 视觉规范

- 前缀沿用本地化 `command.prefix`，不重复添加 `[RollTheDice]`。
- 稀有度颜色沿用现状：
  - 普通 `ChatColors.Default`
  - 稀有 `ChatColors.Green`
  - 史诗 `ChatColors.LightPurple`
  - 传说 `ChatColors.Yellow`
  - 组合 `ChatColors.DarkRed`
- 骰子行：`  ● 名称 [稀有度] — 效果`
- 管理列表：每行最多 3 项，项间两空格；按名称排序；每项为“中文名（类名）”，保证 `!givedice` 的类名参数仍可照抄。
- 诊断信息：一行一个主题，避免 200+ 字符长行。

## 边界

- 不改 `DiceBlueprint`、抽骰池、权重、冷却。
- 不改 `lang/en.json` 中既有 key 的语义；只新增少量 UI key。
- 不把 UI helper 做成配置系统，不引入主题文件。
- 不重构所有 335 处 Dice 内 UI 调用；本轮只覆盖命令面板。

## 验收

- 稀有度颜色与现状完全一致。
- `!rtd status` 排序稳定，数量正确。
- `!givedice` 列表不丢 Dice、不重复。
- 没有新增裸颜色控制字符散落在业务代码里。
