# 法阵刻画重构：从"骨架圆"到"超位魔法阵"设计

日期：2026-09-20
范围：RollTheDice（CS2 / CounterStrikeSharp 1.0.373 / net10.0）
状态：设计已确认，待出实施计划
前置：`2026-09-20-super-tier-magic-trio-design.md`（三件套已上线）

## 1. 背景与问题

用户反馈（原话要点）：法阵**够大够多但不够"密"**；只有"几个棍子"、**太稀疏**；"大小就两种"、
**太规整**；缺少**五芒星**等经典刻画；观感"很一般"。

现状实测（SkyVerdict，半径 520 / 塔半径 620）：

- 地面 `MagicSigil` 3 层，每层只有「1 个圆环 + 若干辐条」，半径按固定 `×0.66` 递减：520 → 343 → 226。
  共约 158 根 CBeam（32 段环 + 12/10/8 根辐条）。
- `MagicTower` 8 层完全同构：20 段/圈 + 6 根辐条、半径恒定 620。共约 368 根。
- 单次 SkyVerdict 总计约 **526 根**。

病灶：**结构贫乏，不是数量不够**。

1. 段数太低 → 32 段/520 半径，单段弦长 ≈100；塔 20 段/620 半径弦长 ≈194 → 远看是多边形不是圆。
2. 辐条 = 均匀长直线 → 即"几个棍子"。
3. 每个圆只有主环 + 外环两个半径 → 即"大小就两种"。
4. 零刻画 → 无五芒星 / 内嵌多边形 / 符文带 / 刻度环。超位魔法的信息量全在这些"铭文层"，不在尺寸。
5. 全同构、共轴、等分 → "太规整"。

## 2. 目标 / 非目标

**目标**

- 法阵从"骨架圆"升级为**多层次刻画法阵**：五芒星、符文带、刻度环、内嵌多边形、多层多尺寸同心环、
  顶点辐条、中心纹章。
- 用**不同半径承载不同刻画**，消除"大小只有两种"与"太规整"。
- **不显著增加每 tick 网络成本**（靠静态/动画分离）。
- 密度与样式**配置可调**（改 JSON 不重编译），并提供安全回退开关。
- 提供 `rtdsigil` 调试指令，可在游戏内即时生成测试阵反复调整。

**非目标**

- 不引入新素材 / 不改工坊 addon / 不动 `scripts/weapons.vdata_c`。
- 不做自定义 vpcf（`docs\research\2026-09-20-cs2-particle-system.md` 已证服务器无法通用缩放/旋转现成 vpcf）。
- 不改三件套的伤害/时长/冷却等玩法数值（本次纯表现层）。
- 不追求"加法混合真发光"（CBeam 是否支持未证实）；用双色描边模拟。

## 3. 路线选择

| 方案 | 做法 | 结论 |
|---|---|---|
| **A. CBeam 分层刻画** | 用十几个不同半径的刻画特征替换"圆+辐条"，双色描边 | **采用**。密度、跟随、收缩、换色全可控，无素材依赖，路径已验证 |
| B. 现成法阵 vpcf 贴图 | 直接铺粒子法阵 | 否决为主结构：服务器不能缩放/旋转/换色，满足不了"锁定准星点 + 倒数收缩 + 跟随"；且 `particles/ui/*` 有屏幕空间风险 |
| C. A + B 混合 | A 当骨架，关键层叠 1-2 个 world-space 法阵贴图补纹样 | **后续增强**（需先确认 VPK 内有可静态摆放的地面法阵贴图）；本次不做 |

粒子层（`PingGroundRings` / `DangerZoneLoop` 等）现状已铺，问题在 CBeam 骨架 → 先补骨架收益最大。

## 4. 要素词汇表（新原语）

所有原语均为服务器端 `CBeam`，无素材依赖。每根线**双色描边**（粗暗底 + 细亮芯）可选。

| 原语 | 参数 | 每实例线数 | 对称性 |
|---|---|---|---|
| `Arc` | 半径、段数、z、自转 | 段数 | 旋转对称（静态） |
| `RuneBand` | 内半径、外半径、根数、z、自转、seed | 根数 | 非对称（动画） |
| `TickRing` | 半径、根数、刻度长、z、自转、seed | 根数 | 非对称（动画） |
| `Star` | 点数、跨步、半径、z、自转 | 点数 | 非对称（动画）。五芒星 = {5/2}；六芒星 = {6/2} |
| `Polygon` | 边数、半径、z、自转 | 边数 | 非对称（动画） |
| `Spokes` | 起半径、止半径、角度表、z、细线 | 角度数 | 非对称（动画） |

**双色描边**：重要线条（外框、五芒星、顶点辐条）画两层——外层 `width×2.4` 深琥珀、内层 `width×1.0` 亮白金。
不用 alpha，不依赖混合模式。

## 5. 地面主法阵组合（以 SkyVerdict R=520 为基准）

| # | 刻画 | 半径 | 数量 | 类型 |
|---|---|---|---|---|
| 1 | 外框粗环 | 1.000 R | 96 段 | 静态 |
| 2 | 外框细环 | 0.965 R | 96 段 | 静态 |
| 3 | 符文带（长短不一 + 随机缺口） | 0.930 → 0.800 R | 84 根 | 动画 |
| 4 | 刻度环 | 0.760 R | 42 根 | 动画 |
| 5 | 大五芒星 {5/2} | 0.700 R | 5 弦 | 动画 |

| 7 | 顶点辐条（5 顶点 → 外环） | 0.700 → 0.965 R | 5 根 | 动画 |
| 8 | 中环 | 0.550 R | 64 段 | 静态 |
| 9 | 八边形（错位旋转） | 0.500 R | 8 边 | 动画 |

| 11 | 六芒星 {6/2} | 0.340 R | 6 弦 | 动画 |
| 12 | 小五芒星（反向旋转） | 0.220 R | 5 弦 | 动画 |
| 13 | 阵眼环 | 0.120 R | 24 段 | 静态 |
| 14 | 阵眼十字 | 中心 | 4 根 | 动画 |

合计 **492 条线**（静态 328、动画 164）。双色描边给 6 项关键刻画各叠一层暗晕 → 实际 CBeam ≈ **613 根**。

> 实施后实测口径：`SigilShape.BeamCount` 按"实际创建的 CBeam 数"计（含晕层），`rtdsigil` 会打印真值。

**半径分数为内部组合常量**（不暴露为配置项——它们描述"长什么样"，不是"调什么"）。

## 6. 静态 / 动画分离（核心工程点）

`Arc` 是旋转对称的，旋转不可见 → 静态环**只在创建时摆一次**，不进每 tick 更新。

- 地面阵每次更新量（每 2 tick）：**164**（现状 158）→ 基本不变。
- 地面阵实体总数：492（现状 158）→ 约 3×。
- 倒数收缩期间：静态环需要改半径，按**每 4 tick 一次**（收缩是慢过程）更新。

### 法阵塔

8 层不再同构。每层 = **1 个细底环**（旋转对称 → 静态）+ **1 种刻画**（动画）；半径 620、`radius_decay` 默认 0：

| 层 | 刻画 | 估算线数 |
|---|---|---|
| 0 | 符文带 | 48 |
| 1 | 五芒星 + 五边形 | 5 + 5 |
| 2 | 八边形 | 8 |
| 3 | 刻度环 | 24 |
| 4 | 六芒星 | 6 |
| 5 | 符文带 | 48 |
| 6 | 五芒星 + 五边形 | 5 + 5 |
| 7 | 顶点辐条 | 6 |

细底环 48 段 × 8 层 = 384（静态）；刻画合计 160 条线（动画）。
塔合计 **544 条线**（静态 384、动画 160）→ 实际 CBeam ≈ **556 根**（4 项刻画带暗晕层），按现有 1/2 频率更新。

单次 SkyVerdict ≈ 613 + 556 = **1169 根**（现状 526）；其中每 2 tick 需更新的仅地面 164 + 塔 160 = **324 根**（现状 526 全部更新）→ 实体约 2.2×，每 tick 网络成本约 0.62×。

`FinalJudgment` 结构同 SkyVerdict（地面阵 + 8 层塔），数值各自配置。

## 7. "太规整"的破除

- 符文带：**确定性伪随机**（按刻画索引 + `seed` 做整数哈希）决定每根刻度长度与是否缺口 → 像真铭文，且每次施法一致可复现。
- 各层自转用无理数角度错位，非共轴。
- 三层配色：亮白金芯 + 中金 + 深琥珀晕。
- 色彩主题：SkyVerdict 铂金；FinalJudgment 金 → 暗红；DivineDescent 纯金白。

## 8. 配置项（每个 dice config 新增）

| 键 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `sigil_style` | string | `"arcane"` | `"arcane"` 新刻画 / `"legacy"` 现状（安全回退） |
| `sigil_density` | float | `1.0` | 全局密度倍率（0.5–2.0），缩放段数与刻度量 |
| `rune_ticks` | int | `84` | 符文带根数 |
| `tick_ring_count` | int | `42` | 刻度环根数 |
| `star_points` | int | `5` | 主星点数（5=五芒星，6=六芒星） |
| `star_skip` | int | `2` | 星形跨步（{n/skip}） |
| `polygon_sides` | int | `8` | 中带内嵌多边形边数 |
| `double_line` | bool | `true` | 双色描边 |
| `sigil_seed` | int | `0` | 确定性变化种子 |

半径分数、各层自转方向、静态环段数（96/64/48/24）保持内部常量，`sigil_density` 统一缩放。

## 9. 架构与落点

- 新增 `RollTheDice.Utils\SigilShapes.cs`：原语（`Arc` / `RuneBand` / `TickRing` / `Star` / `Polygon` / `Spokes`），
  每个原语实现 `Update(center, time, scale)` + `Remove()`，内部自带静态/动画标志与双色描边。
- 新增 `RollTheDice.Utils\ArcaneSigil.cs`：按"组合表"组装地面主法阵与塔层，实现 `Update/Remove`。
- `MagicSigil` / `MagicTower` 改为堆叠 `ArcaneSigil`（保留公开签名，尽量不动调用点）。
- `MagicCircle` 保留（`DivineDescent`、`dicefx` beams）→ 轻量升级为"外框 + 中心纹章"即可，不强制套用完整组合。
- `BeamFx` 复用（`Create` / `Move` / `Kill`）；`Move` 的 `SetStateChanged(..., "m_vecEndPos")` 不可去掉。
- 调试指令 `rtdsigil [半径] [密度] [style]`（需 `@rollthedice/admin`）：在准星命中点生成测试阵，像现有 `rtdeffect`。

## 10. 性能预算与风险

- 单帧创建 ~1169 实体可能有**瞬时卡顿**（现状 526 已有）。缓解：可选**分 2-3 tick 错峰创建**；或实测爆卡后降 `sigil_density`。
- 两个终极同时施放 → 约 2338 实体 + 粒子。需实测帧率。
- 每 2 tick 状态更新：地面 164 + 塔 160 = 324（现状 526），量级更低。
- CBeam 加法发光未证实 → 双色描边兜底，不虚报。
- `Arc` 静态化的前提是"旋转对称"，实现时不得给静态环叠加任何非对称装饰。
- 效果只能在游戏内评估 → 以 `rtdsigil` 为准迭代。

## 11. 验证方式

- 编译：`dotnet build RollTheDice.csproj -c Release`（`--no-incremental` 确认真编译）。
- 几何可测：五芒星顶点落在圆上、星形跨步正确、刻度量 = 配置值、`scale` 正确作用于所有半径。
- 生命周期：`Remove` 后无残留 CBeam；`Reset`/`Destroy` 全覆盖。
- 实机：`rtdsigil` 生成 → 观察密度/规整度/可读性；SkyVerdict 实放观察倒数收缩与跟随。
- 对比：同一场景下记录 fps 与实体数（与现状 526 对照）。

## 12. 不破坏的不变量

- 不动伤害/冷却/无敌/白屏/震屏等玩法逻辑。
- `SkyVerdict` / `FinalJudgment` 的 `Remove` **仍不清 pending**（终极被死亡取消的 bug 修不回退）。
- 所有 CBeam 在 `Remove`/`Reset`/`Destroy` 对称清理，无泄漏。
- 仅服务真人（沿用现有过滤）；不新增对 BOT 的表现。
